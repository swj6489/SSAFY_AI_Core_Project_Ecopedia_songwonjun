# EcoPedia 요구사항과 RAG 설계

## 목표와 도메인

국내 멸종위기 야생생물에 대해 근거가 필요한 생태 질문에 답한다. 취향에 따른 추천 점수는 사용하지 않는다. 기준 목록은 국립생태원 2022년 개정 282종이다. 데이터 규모·중복·이용 조건 검토는 이전 데이터 확보 단계의 결과를 따른다.

대표 질문은 삵의 서식지 훼손, 산양과 사향노루의 서식 환경 비교, 하천 개발의 멸종위기 어류 영향이다. 서식지·위협 요인 값은 승인된 자료에서만 추가한다.

## 두 컬렉션과 메타데이터

`species_meta`는 종 한 건을 한 청크로 색인한다. 국명·학명·분류군·숫자 등급·국내 분포·서식 환경·주요 위협 요인·기준일을 텍스트로 구성한다. 미확인 속성은 명시적으로 표시한다.

메타데이터 필드: `species_id`, `korean_name`, `scientific_name`, `taxon_group`, `endangered_grade`(정수), `source_url`, `source_basis_date`, `source_type=metadata`, `document_title`, `chunk_id`.

`species_docs`는 외부 문서를 1000자, 중복 200자로 분할한다. PDF 페이지 경계를 유지하며, 청크는 문단 경계를 우선한다.

문서 메타데이터 필드: `species_id`, `document_id`, `document_title`, `source_type`, `source_url`, `source_file`, `page_number`(PDF만), `chunk_index`, `chunk_id`, `content_hash`, `search_query`, `collected_at`, `license`, `revision_id`.

식별자는 `meta:{species_id}`, `doc:{species_id}:{document_id}:{chunk_index}`다. 종 ID는 최초 부여한 값을 데이터 파일에 영구 보존한다. 학명은 이름 변경과 무관한 내부 ID를 대체하지 않는다. 동일 문서가 여러 종에 연결되어도 서로 덮어쓰지 않는다.

색인은 upsert 방식이다. 문서 재분할 후 기존의 불필요한 잔여 청크를 제거한다. 임베딩 프로필은 모델명·서버 주소를 확인하여 서로 다른 임베딩을 섞지 않는다.

## 수집과 색인

1. 종 정보와 질문으로 검색어 추출 프롬프트 실행.
2. 프로그램이 종명·학명 검색어를 강제 포함.
3. 종 자체의 위키 문서 일치 확인. 동음이의는 제외. 상위 분류군 리다이렉트는 동일 학명이 확인되지 않으면 자동 강제 포함하지 않음.
4. 종 자체 문서는 선별·길이 제한과 무관하게 수집·색인.
5. 관련 검색어로 후보 제목·요약 확보.
6. 후보 선별 프롬프트로 주어진 ID 중 관련 문서만 선택.
7. 본문·리비전·출처·라이선스를 수집하고 SQLite에 보관.
8. 페이지/문단별 청킹 및 별도 문서 컬렉션 색인.
9. 성공한 검색어만 완료 캐시. 실패 시 재시도 가능. 성공한 검색어·종 문서 확인 결과·문서 본문은 만료 없이 영구 재사용하며 재시작 후에도 재수집하지 않음(NF2002). 기존 SQLite 기록은 유지하고 청크 설정 변경 시 저장된 본문만 다시 분할·색인함.

기본 자동 소스는 한국어 위키백과 텍스트다. 권리 미확정 공식 도감·국립생물자원관 본문은 자동 수집하지 않는다. 승인된 PDF/TXT는 manifest로 대체 수집한다. 외부 API는 1초 간격, 30초 타임아웃, 재시도와 Retry-After를 적용한다.

## 프롬프트

`ecopedia/prompts.py`에서 역할과 JSON 출력 형식을 관리한다.

| 프롬프트 | 입력 | 출력 |
|---|---|---|
| 검색어 추출 | 선택 종과 질문 | `queries` 문자열 배열 |
| 후보 문서 선별 | 종·질문·후보 ID/제목/요약 | ID·선택 여부·이유 배열 |
| 답변 생성 | 질문·최근 대화 맥락·번호가 부여된 근거 | 답변·사용 근거 번호 |
| 조건 탐색 보조 | 자연어 조건·메타데이터 검색 후보 | 조건 충족을 확인한 종 ID·이유 |

JSON 출력은 strict JSON Schema로 요청한다. 파싱 실패는 한 번 형식 교정을 요청한 뒤 오류 처리한다. 존재하지 않는 후보 ID는 버린다. 문서 내용의 지시는 따르지 않도록 프롬프트로 제약한다. 이것은 사실 정확성을 보장하는 검증을 대체하지 않는다.

## 검색과 답변

질문 전 수집 작업 후 LangGraph의 `retrieve → generate`를 실행한다. 그래프 노드는 두 개다.

`retrieve`: 종당 메타데이터 1개를 필수 포함하고 `species_id` 필터로 외부 문서 상위 4개를 검색한다. 이 중 최소 한 슬롯은 확인된 종 자체 문서의 관련 청크를 우선한다. 한 종 최대 5개, 두 종 최대 10개. 청크 ID와 공백 정규화 본문 해시로 중복을 제거한다. 비교 시 같은 문서라도 두 종의 소유 관계를 보존한다.

`generate`: 이번 근거만 사실 정보로 사용하고 주요 주장에 `[근거 N]`을 붙인다. 국가적색목록·IUCN 등급과 법정 1·2급을 구분한다. 확인되지 않는 정보는 모른다고 답하도록 제약한다. 잘못된 근거 번호는 재생성 한 번 후에도 실패하면 답변 표시를 거부한다.

화면은 답변 본문에 등장하는 실제 인용 번호를 기준으로 근거를 표시한다. LLM이 별도로 반환한 used-ID 배열은 신뢰하지 않는다. 문서 제목·원문 링크·출처 유형·PDF 파일명 및 페이지·라이선스를 표시한다. 인용이 없으면 안내한다.

## 검색 설정 선택 이유

초기값은 청크 1000자·중복 200자·외부 Top-k 4다. 생태 설명의 문맥을 보존하면서 입력량을 제한하는 출발점이며 품질 최적화 결과가 아니다. 비교값은 600/1000/1400자, 중복 100/200자, Top-k 2/4/6이다. 한 설정씩 바꿔 근거 재현율·중복·답변 정확성·응답 시간을 비교한다.

MMR 선택 시 후보 20개에서 다양성을 반영해 4개를 고른다. `mmr_lambda=0.5`. 두 검색 방식의 실행 경로는 준비했지만 실제 생태 질문으로 품질 비교하지는 않았다.

## 화면 및 특화 기능

사이드바에서 종명·분류군·등급으로 선택한다. 채팅·조건 탐색·두 종 비교의 세 탭이다. 대화는 종 ID별 세션 저장이며 브라우저 세션을 넘어 영구 보관하지 않는다.

조건 탐색은 메타데이터 의미 검색 후 LLM 선별을 적용한다. 명시적 등급·분류군 조건은 DB 필터로 먼저 제한한다. 후보 20개 대상이므로 모든 조건 부합 종의 전수 목록은 보장하지 않는다. 카드에서 종별 질문 화면으로 연결한다.

특화 기능은 두 종 생태 비교다. 종마다 따로 검색하여 분포·서식 환경·위협 요인을 근거와 함께 표로 비교하도록 요청한다. 문서에 없는 값은 추측하지 않는다.
