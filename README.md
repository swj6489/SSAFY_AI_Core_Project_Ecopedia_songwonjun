# EcoPedia — 국내 멸종위기 야생생물 백과

282종의 공식 목록을 바탕으로 종을 찾고, 외부 설명 문서를 검색해 근거가 붙은 답변과 두 종 생태 비교를 제공하는 Python 프로젝트입니다.

## 바로 실행

현재 작업 PC에는 `.venv`에 명세의 라이브러리 버전을 설치했고 로컬 `.env`에 GMS 연결 설정을 완료했습니다. PowerShell에서 이 폴더로 이동한 다음 실행합니다. 현재 PC의 `.env`를 예시 파일로 덮어쓰지 마세요.

```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py
```

다른 PC에서는 Python 3.10 이상(검증 버전 3.12)으로 설치합니다.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

또는 `run.ps1`을 실행합니다. 키 없이도 282종 목록·분류군·등급 필터를 사용할 수 있습니다. AI 채팅 및 임베딩은 API 키가 필요하며 사용료가 발생할 수 있습니다.

1. `.env.example`을 `.env`로 복사합니다.
2. `.env`에 `OPENAI_API_KEY`를 설정합니다. 키를 소스나 채팅에 붙이지 않습니다.
3. GMS는 `OPENAI_BASE_URL=https://gms.ssafy.io/gmsapi/api.openai.com/v1`을 사용합니다. 현재 채팅 모델은 `CHAT_MODEL=gpt-5.4-mini`이며 실제 GMS 구조화 JSON 응답을 검증했습니다. 임베딩은 기존 `text-embedding-3-small`을 유지하므로 모델 변경 때문에 재색인할 필요는 없습니다. GMS 키를 SDK 호환 환경변수인 `OPENAI_API_KEY`에 넣습니다.
4. 위키백과 수집을 쓰려면 `WIKIMEDIA_USER_AGENT`에 프로젝트명과 실제 이메일 또는 프로젝트 연락 URL을 설정합니다. 허구의 연락처는 기본값으로 넣지 않았습니다.
5. 앱을 실행하고 사이드바의 **종 메타데이터 색인**을 누릅니다.
6. 종을 선택하고 질문합니다. 같은 검색어는 캐시를 사용합니다.

예시 User-Agent 형식: `EcoPedia/0.1 (본인의 실제 연락 이메일 또는 프로젝트 URL)`.

환경변수는 앱 프로세스 시작 시 읽습니다. `.env`를 바꿨으면 서버를 재시작하세요. OS에 이미 있는 환경변수가 `.env`보다 우선합니다. 잘못된 키·모델·서버에서 발생한 상세 오류는 화면 대신 `runtime/app.log`에 기록됩니다.

## 구현 기능

종별 질문 화면의 ‘어떤 점이 궁금하세요?’에서 추천 질문을 선택할 수 있습니다. 기본 정보·특징 요약을 항상 제안하고, 생태 질문은 현재 저장 자료에 원문 대조 정보 또는 관련 근거가 있는 항목만 제공합니다. 버튼은 해당 종의 입력창에 질문을 채우기만 하며 AI·수집·임베딩을 호출하지 않습니다. 사용자가 문장을 수정하고 전송한 뒤에만 기존 질문 처리를 실행합니다. 종별 입력창을 분리하여 다른 종에 이전 추천 질문이 잘못 전송되지 않도록 했습니다. 추천 표시는 실제 답변 정확성·최신성 보장이 아닙니다.

종별 질문 화면의 ‘정보 확보 상태’에서 서식 환경·국내 분포·주요 위협 요인을 확인할 수 있습니다. `정보 확보`는 메타데이터에 유효한 값이 있는 경우, `관련 근거 있음`은 학명과 종 문서가 일치하는 기존 수집 본문에서 관련 표현을 자동 검출한 경우, `미확보`는 저장된 자료에서 해당 설명을 아직 찾지 못한 경우입니다. 관련 근거 있음은 사실 검증 완료나 최신성 보장이 아니며, 미확보는 실제로 정보가 존재하지 않는다는 뜻이 아닙니다. ‘판별 기준과 항목별 근거 보기’에서 원문 문장·출처·라이선스·문서 리비전 등을 확인할 수 있습니다. 해외 분포나 보호 등급만으로 국내 분포·위협 요인을 확보했다고 표시하지 않습니다.

상태 계산 자체는 로컬 캐시만 읽으며 AI·임베딩·외부 수집 호출과 메타데이터 변경이 없습니다. 별도 생태 정보 보강은 아래 절을 참고하세요. `원문 대조 정보`는 자동 추출한 인용이 저장 원문·항목 검사에 통과한 경우입니다. 기존 캐시를 지우거나 다시 수집하지 않습니다. 질문 후 자료가 새로 저장되면 화면을 다시 그려 상태를 갱신합니다. 규칙 기반 자동 탐지는 누락·오탐 가능성이 있으므로 실제 답변 가능 여부는 질문 시 검색된 근거에 따라 달라집니다.

사이드바 상단 ‘화면 모드’에서 라이트·다크를 즉시 전환할 수 있습니다. 배경·카드·입력창·드롭다운·대화창·배지·사진 영역에 공통 색상 변수를 적용했으며 선택한 종·대화·검색 조건은 전환해도 유지됩니다. 선택한 모드는 현재 브라우저 세션 동안 유지되고, 새 세션은 라이트로 시작합니다. OS/Streamlit 설정 자체를 변경하는 기능은 아니며 앱 안의 표시 모드입니다. 사이드바는 브랜드 카드, 탐색 메뉴, 종 찾기, 이용 상태, 데이터 관리 영역으로 구분했습니다. 색상 팔레트는 `ecopedia/ui.py`의 `PALETTES`에서 관리합니다.

화면은 숲색·웜 화이트 테마로 구성했습니다. 상단 브랜드 배너, 종 정보·등급 배지와 대표 이미지 프로필, 2열 검색 결과 카드, 독립된 두 종 비교 선택 카드, 키워드 버튼을 제공합니다. 사진 저작자·라이선스·원문 링크는 각 이미지의 ‘사진 출처·이용 조건’ 펼치기에 보존하고, 퍼블릭 도메인·CC0 표시는 바로 보이도록 유지합니다. 색인 버튼은 사이드바 ‘데이터 관리’에서 사용할 수 있습니다. 모바일 폭에 맞춘 레이아웃과 키보드 포커스 표시도 추가했습니다. 테마 설정 변경 후에는 Streamlit 서버를 재시작하세요. 화면 스타일은 `ecopedia/ui.py`, 기본 테마는 `.streamlit/config.toml`에서 관리합니다.

- 종 목록 282건, 고정 내부 ID, 국명·학명 검색, 분류군 및 숫자 등급 필터.
- `Ⅰ급`, `I급`, `1급` 및 `Ⅱ급`, `II급`, `2급` 입력 정규화.
- `species_meta`, `species_docs` 두 개의 영속 Chroma 컬렉션.
- 검색어 추출, 후보 문서 선별, 근거 기반 답변 생성 프롬프트.
- 위키백과 종 자체 문서는 후보 선별·길이 제외보다 우선 색인. 종 일치를 확인할 수 없으면 안내.
- 문서 본문과 검색어 캐시, HTTP 재시도·호출 간격·타임아웃·User-Agent.
- LangGraph `retrieve → generate` 두 노드.
- 선택한 종의 메타데이터 강제 포함, 종 ID로 외부 청크 범위 제한, 결과 병합·중복 제거.
- 주요 주장 근거 번호, 유효한 번호 검증, 본문에 실제 인용된 청크만 표시.
- 종별 세션 대화 기록, 자연어 조건 탐색과 종 선택 연결, 두 종 생태 비교.
- 두 종 비교는 ‘첫 번째 종’과 ‘두 번째 종’ 선택 영역을 분리해 국명·학명 검색, 분류군·등급 필터를 각각 제공합니다. 두 번째 목록에서는 첫 번째 종을 제외하며, 서로 다른 두 종을 선택해야 비교 버튼을 사용할 수 있습니다.
- 자연어 조건 탐색 상단에 등급·분류군 키워드 버튼 제공. 예: `2급` + `포유류` 선택 → `2급 포유류 찾아줘` 자동 입력. 직접 수정 후 ‘조건으로 찾기’로 검색하며 키워드 선택만으로 API를 호출하지 않습니다. 같은 키워드를 다시 누르면 해제되고, 초기화 버튼은 키워드·입력·검색 결과를 지웁니다. 자료가 없는 서식지·분포는 추천 키워드에 포함하지 않았습니다.
- 종별 질문 화면과 자연어 조건 검색 결과에 대표 사진 표시. 학명이 문서에서 확인되고 파일별 저작자·허용 라이선스가 확인된 사진만 사용하며, 사진 원문·저작자·라이선스를 함께 표시합니다.
- 로컬 PDF/TXT 문서 묶음 수집 대체 경로. 이용 조건 확인이 필요한 manifest 방식.
- 진행 상태, 색인 없음·키 누락·근거 없음·연결 실패 안내.
- 선택 기능: MMR 검색 및 RAG 전후 답변을 저장하는 평가 명령.

## 현재 데이터의 범위

`data/species.json`에는 국명·학명·분류군·법정 등급·출처·기준일을 담았습니다. 국립생태원에서 내려받은 목록의 **2022-12-09 개정 기준**이며 2026년 현행 법령과 전수 대조하지 않았습니다. 1급 68종, 2급 214종입니다.

원본 목록에는 서식 환경·국내 분포·위협 요인이 없어 해당 필드는 빈 문자열로 보존합니다. 외부 문서에서 보강한 정보는 별도 캐시와 파생 색인에 출처를 붙여 저장하며, 종별 답변·비교·자연어 조건 탐색에서 함께 사용합니다. 원본 필드가 비었다는 이유만으로 외부 근거까지 없다고 판단하지 않습니다. 실제로 근거를 확보하지 못한 항목은 계속 미확보로 표시합니다.

### 생태 정보 보강

`ecopedia/ecology.py`는 같은 종임을 확인한 저장 문서에서 AI가 원문 인용을 추출하고, 페이지·문장 일치·항목 관련 표현을 검증합니다. 화면의 `원문 대조 정보`는 이러한 자동 대조를 통과했다는 뜻이며, 사람의 사실 검증이나 최신성 보장이 아닙니다. 과거 기록과 시점 미확인을 구분하며 원문 URL·리비전·라이선스·수집 시각·추출 시각을 보존합니다. 답변은 영문 인용도 한국어로 설명할 수 있습니다.

```powershell
# 기존 캐시만 사용한 추출 (AI/임베딩 호출료 발생 가능)
.\venv\Scripts\python.exe -m ecopedia.cli enrich-ecology --limit 20

# data/ecology-priority.json의 대표 20종: 없는 종 본문만 수집, 필요할 때 영문 위키백과 보완
.\venv\Scripts\python.exe -m ecopedia.cli enrich-ecology --collect-missing --english-supplement --limit 20

# 지정한 종의 누락 항목만 저장된 원문에서 명시적으로 재검토 (AI 호출료 발생)
.\venv\Scripts\python.exe -m ecopedia.cli enrich-ecology --species-ids sp_0202 --retry-incomplete
```

기존 본문을 지우거나 다시 내려받지 않습니다. `ecology:v1` 키에 종 ID·문서 ID·본문/리비전 지문으로 추출을 캐시하고, 동일 추출과 색인은 재사용합니다. 성공한 빈 결과도 저장합니다. `--retry-rejected` 또는 `--retry-incomplete`를 명시했을 때만 해당 저장 문서를 재추출합니다. 실패한 연결은 재시도할 수 있습니다. 영문 보완은 별도 학명 조회 캐시를 사용합니다. 한국어 문서의 제목은 일치하나 소개에 학명이 없으면 Wikidata의 정확한 P225를 추가 확인할 수 있습니다. 괄호 안 아속명만 선택 표기로 처리하며 실제 아종명이나 다른 종을 임의로 합치지 않습니다.

보강 결과는 `runtime/source-cache.sqlite3`와 기존 `species_docs` 컬렉션에 저장됩니다. 위키백과 원문에서 발췌·분류한 변경 고지를 표시하고 해당 자료의 CC BY-SA 조건을 유지합니다. 별도 세 번째 컬렉션이나 근거 없는 AI 생성 생태정보를 추가하지 않습니다. 자연어 조건 탐색은 후보 기반 검색이므로 전체 282종 전수 결과를 보장하지 않습니다. 원본 공식 목록의 이용허락 검토는 별도입니다.

원본의 `양서파충류`를 임의로 양서류·파충류로 분리하지 않았습니다. `곤충`, `식물`도 원본 분류명을 보존했습니다. 원본과 공식 도감 사이 학명 차이가 확인된 하늘다람쥐·염주알다슬기는 별도 검토가 필요합니다.

초기 `sp_0001` 등의 ID는 최초 목록에서 한 번 부여했습니다. 이름·학명·정렬 순서가 바뀌어도 기존 `species_id`는 유지하세요. 다른 항목으로 ID를 재사용하지 마세요.

## 문서 수집과 이용 조건

국립생태원 공식 도감과 국립생물자원관 설명문은 이용 조건 미확정/변경금지 문제가 있어 **자동 수집 소스에 포함하지 않았습니다**. 다운로드 원본도 앱 패키지에 넣지 않았습니다. 기본 자동 수집 소스는 한국어 위키백과의 텍스트입니다.

위키백과 텍스트는 기본 CC BY-SA 4.0 조건에 따라 원문·리비전·라이선스를 저장합니다. 문서별 예외를 확인하고, 재사용·개작한 자료를 공유할 때 출처표시·변경 고지·동일조건 적용 범위를 준수해야 합니다. 코드 전체가 위키백과 라이선스로 바뀐다는 의미는 아닙니다.

대표 사진은 별도로 MediaWiki PageImages/Imageinfo API에서 조회합니다. 종의 학명이 문서 소개에 나타나는지 확인하고, 동음이의 문서와 SVG 아이콘 등을 제외합니다. JPEG/PNG/WebP 파일 중 CC BY, CC BY-SA, CC0, Public domain 또는 공공누리 제1유형(KOGL Type 1) 표시와 저작자·출처가 확인된 자료만 표시합니다. 공공누리 제2~4유형은 자동 표시하지 않습니다. 텍스트 라이선스를 사진에 일괄 적용하지 않습니다. 이미지 자체를 다운로드하거나 벡터 색인하지 않고 원격 썸네일 URL을 표시합니다. 파일명·사진 URL·저작자·라이선스·원문 URL·확인 시각은 `runtime/source-cache.sqlite3`에 만료 없이 저장합니다. 사진이 없는 성공 결과도 재조회하지 않으며, 네트워크 실패만 다음 실행에서 재시도합니다. 사진 기능은 GMS 키 없이도 동작하지만 실제 연락처가 포함된 `WIKIMEDIA_USER_AGENT`와 인터넷 연결이 필요합니다. 첫 조회 때만 외부 API를 사용하며, 사진 확인에 실패해도 질문 기능을 막지 않습니다.

- 종 목록 원문: https://www.nie.re.kr/nie/pgm/edSpecies/edSpeciesList.do
- 종 목록 다운로드: https://www.nie.re.kr/nie/cmmn/file/fileDown.do?atchFileId=65e8ae569f7e4520b6106ffdf92c3161&fileSn=1
- 국립생태원 정책: https://www.nie.re.kr/nie/main/contents.do?menuNo=200232
- 위키미디어 이용 조건: https://foundation.wikimedia.org/wiki/Policy:Terms_of_Use/en#7._Licensing_of_Content
- MediaWiki API: https://www.mediawiki.org/wiki/API:Main_page

종 목록의 개별 이용허락은 확인이 남아 있습니다. 본 패키지의 사실 필드는 교육용 검토 자료이며, 배포용 권리 확인이 끝난 데이터라고 표시하지 않았습니다. 기존 확인 문서는 프로젝트와 같은 상위 `outputs` 폴더의 `멸종위기종_도메인확인`에 있습니다.

위키백과에서 282종 모두의 문서를 찾는다고 보장하지 않습니다. 동음이의 문서·상위 분류군으로의 모호한 리다이렉트는 종 자체의 문서로 강제 색인하지 않습니다. 동일 종이 확인되지 않으면 이용 가능한 종별 문서를 manifest로 추가하세요.

## 명령줄 데이터 관리

### 대표 사진의 대체 검색

기존 대표 사진과 Commons 퍼블릭 도메인·CC0 검색에도 사진이 없으면 Wikidata 경로를 추가로 사용합니다. 학명으로 후보 항목을 찾고 **P225(학명)가 목록의 학명과 정확히 일치하는지** 검증한 뒤 P18(대표 이미지) 파일을 Commons에서 조회합니다. 폐기된(deprecated) 문장은 제외하며, 이름이 비슷한 종이나 상위 분류군으로 임의 대체하지 않습니다. 이 경로 역시 **Public domain·CC0만 대체 사진으로 허용**합니다. CC BY·CC BY-SA 허용 범위를 추가로 넓힌 것은 아닙니다. 화면에는 Wikidata 학명 확인 안내와 항목 링크를 함께 표시합니다.

Wikidata 항목·파일 연결과 최종 사진 결과는 별도 캐시로 영구 저장합니다. 이전 ‘사진 없음’ 캐시가 있어도 이 새로운 경로만 최초 조회하며, 기존 위키백과·Commons 검색을 다시 수집하지 않습니다. 파일 조회 실패 시 검증한 Wikidata 연결은 보존하여 다음 시도에서 재활용합니다. 학명 변경·아종 또는 이미지 이용 조건 때문에 새 경로에서도 사진이 없을 수 있습니다.

기존 대표 사진이 없으면 Wikimedia Commons에서 해당 학명으로 최대 20개 후보를 추가 검색합니다. 후보의 파일명·설명·분류에 학명이 나타나고, 파일별 조건이 Public domain 또는 CC0로 확인된 사진만 대체 표시합니다. 무료 이용이 가능한 CC BY/CC BY-SA/공공누리 사진을 ‘저작권 없음’으로 바꾸어 표시하지 않습니다. Public domain에는 ‘저작권 제한 없는 사진 · 퍼블릭 도메인 (원문 표기 기준)’, CC0에는 ‘저작권 제한 없는 사진 · CC0 (권리 포기 선언)’을 표시합니다. 출처와 원문 이용 조건 링크는 유지합니다. 퍼블릭 도메인 여부는 원문 표기 기준이며 전 세계의 모든 권리 면제를 보증하지 않습니다. CC0 설명: https://creativecommons.org/publicdomain/zero/1.0/

기존 대표 사진 캐시는 다시 수집하지 않습니다. 대체 검색 결과는 별도 `photo-pd:v1` 캐시로 영구 재사용하고, 결과가 없었던 성공 요청도 반복하지 않습니다. 통신 실패만 재시도합니다. 정확히 같은 종의 적절한 사진을 찾지 못하면 사진 없음 안내를 유지합니다. 모든 종의 사진 확보를 보장하지 않으며, 특히 목록 학명과 현재 학명이 다른 종은 별도 검토가 필요합니다.

```powershell
# 키 없이 282종과 등급 수 확인
.\.venv\Scripts\python.exe -m ecopedia.cli check-data

# 종 메타데이터 색인. 같은 ID는 갱신되므로 중복 증가 없음
.\.venv\Scripts\python.exe -m ecopedia.cli index-metadata

# 실제 검색어·선별/제외 결과 확인. 종 ID는 species.json에서 확인
.\.venv\Scripts\python.exe -m ecopedia.cli collect sp_0001 "늑대의 서식 환경과 위협 요인은?"

# LangGraph 구조 출력
.\.venv\Scripts\python.exe -m ecopedia.cli graph

# 청크 설정 변경 후 캐시 본문만 다시 분할·색인
.\.venv\Scripts\python.exe -m ecopedia.cli reindex-documents

# 승인된 로컬 문서 묶음 읽기
.\.venv\Scripts\python.exe -m ecopedia.cli import-documents data/local-documents.json

# 대표 질문 5개 RAG 전후 실제 답변 저장. LLM 호출료 발생
.\.venv\Scripts\python.exe -m ecopedia.cli compare-rag data/evaluation-questions.json
```

`data/local-documents.example.json`은 비활성 예시입니다. 실제 문서·출처·이용 조건 근거를 채우고 `license_confirmed`를 확인한 뒤 `local-documents.json`으로 저장하세요. PDF는 해당 종의 **PDF 파일 기준 페이지 번호(1부터)**를 지정합니다. 이미지 PDF는 OCR 처리가 필요합니다. 입력 파일 경로는 manifest 파일 위치를 기준으로 해석합니다.

`auto_collect`를 `false`로 바꾸면 질문 시 외부 수집을 생략하고 기존 색인만 사용합니다. 성공적으로 수집한 검색어·종 문서 확인 결과·문서 본문은 만료 없이 영구 재사용합니다(NF2002). 앱을 재시작하거나 시간이 지나도 다시 수집하지 않으며, 기존 SQLite 캐시도 그대로 사용합니다. 수집 성공 전에 실패한 검색어는 완료 처리하지 않아 재시도할 수 있습니다. 청크 설정 변경 시에는 저장된 본문을 로컬에서 다시 분할·색인합니다. 수집 캐시 파일을 직접 삭제하면 기록이 없어져 다시 수집하게 되므로 유지해야 합니다.

## 검색 설정

`config.json`에서 문자 기준 청크 1000자·중복 200자·외부 문서 종당 Top-k 4개를 조절합니다. 종 메타데이터는 항상 1개를 포함하므로 한 종 질문 최대 5개, 두 종 비교 최대 10개의 근거를 구성합니다. 중복 제거 후 실제 개수는 줄어들 수 있습니다.

- `search_type`: `similarity` 또는 `mmr`.
- `mmr_fetch_k`: MMR 후보 20개.
- `mmr_lambda`: 관련성·다양성 비중 0.5.
- `catalog_candidates`: 자연어 조건 탐색 후보 20개. 전수 목록이 아닌 후보 검색임.
- PDF는 페이지 경계를 유지하고 페이지 안에서만 청킹.
- 청크 설정을 변경하면 `reindex-documents` 실행. 같은 문서의 낡은 잔여 청크도 제거.
- 임베딩 모델·서버 변경 시 기존 벡터와 섞지 않도록 인덱스 프로필 검사. 별도 runtime 디렉터리에서 새 색인 필요.

## 검증

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

실제 ChromaDB와 LangGraph 및 Streamlit AppTest를 실행합니다. 테스트에서만 결정적 시험용 임베딩과 LLM 대역을 사용하며, 앱에서는 OpenAI 호환 API를 사용합니다. 테스트가 통과해도 실제 LLM의 사실 정확성·문서 적합성·응답 속도가 검증된 것은 아닙니다.

GMS 채팅·1536차원 임베딩 연결, 실제 282종 색인, 위키백과 수집, 종별 답변·비교·모르는 질문 처리 및 실제 API를 사용하는 Streamlit AppTest까지 검증했습니다. NF2002 영구 캐시 수정 후 자동 테스트는 21개를 통과했습니다. 이 소수 사례 검증이 모든 종의 답변 정확성을 보장하지는 않습니다. F2015의 5개 질문 전후 평가와 상호 검증은 아직 수행하지 않았습니다. HTML/CSS/JavaScript 별도 프론트엔드(F2013)는 구현 범위에 포함하지 않았습니다.

JSON 출력은 공식 OpenAI 문서에 맞춘 `response_format=json_schema`의 strict schema로 보강했고, 사실 답변의 인용 누락은 재생성을 요청합니다. GMS 공식 모델별 안내에서 서버 주소를 확인했습니다.

- GMS 채팅 안내: https://gms.ssafy.io/api/v1/guides/gpt-4o-mini
- GMS 임베딩 안내: https://gms.ssafy.io/api/v1/guides/text-embedding-3-small
- OpenAI 구조화 출력: https://developers.openai.com/api/docs/guides/structured-outputs

ZIP 패키지에는 실제 키·이메일이 담긴 `.env`, 가상환경, 수집 캐시·로그·벡터 DB를 포함하지 않습니다. 다른 PC에서 ZIP을 사용하면 `.env` 설정과 색인을 다시 해야 합니다.

이번 단계의 구현·테스트 범위는 `docs/검증결과.md`를 확인하세요. 셀프·상호 체크리스트 및 실제 화면 증빙은 프로젝트 최종 검증에서 추가해야 합니다.
